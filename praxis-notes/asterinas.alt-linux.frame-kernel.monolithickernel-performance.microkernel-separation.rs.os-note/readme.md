However, there’s a twist—the kernel is partitioned in two halves: the OS Framework (akin to a microkernel) and the OS Services. Only the OS Framework is allowed to use unsafe Rust, while the OS Services must be written exclusively in safe Rust. // 在框架内核架构中，整个操作系统位于同一地址空间（类似于单内核），并且必须用 Rust 编写。然而，这里有个特殊之处——内核被分为两部分：操作系统框架（类似于微内核）和操作系统服务。只有操作系统框架可以使用不安全的 Rust 代码 ，而操作系统服务必须完全用安全的 Rust 代码编写。 /// As a result, the memory safety of the kernel can be reduced to that of the OS Framework, thus minimizing the Trusted Computing Base (TCB) associated with the kernel’s memory safety. On the other hand, the single address space allows different parts of the kernel to communicate in the most efficient means, e.g., function calls and shared memory. Thanks to the framekernel architecture, Asterinas can offer both exceptional performance and enhanced safety. // 因此，内核的内存安全性可以降低到操作系统框架的水平，从而最大限度地减少与内核内存安全性相关的可信计算基（TCB）。另一方面，单一地址空间允许内核的不同部分以最高效的方式进行通信，例如函数调用和共享内存。得益于帧内核架构，Asterinas 能够同时提供卓越的性能和增强的安全性。 /// While the concept of framekernel is straightforward, the design and implementation of the required OS framework present challenges. It must concurrently fulfill four criteria. // 虽然帧内核的概念很简单，但所需操作系统框架的设计和实现却面临挑战。它必须同时满足四个标准。 /// - Soundness. The safe APIs of the framework are considered sound if no undefined behaviors shall be triggered by whatever safe Rust code that a programmer may write using the APIs: as long as the code is verified by the Rust toolchain. Soundness ensures that the OS framework, in conjunction with the Rust toolchain, bears the full responsibility for the kernel’s memory safety. // 健全性。 该框架的安全 API 被认为是可靠的。 如果程序员使用 API 编写的任何安全的 Rust 代码都不会触发任何未定义行为：只要代码通过了 Rust 工具链的验证，可靠性就能确保操作系统框架与 Rust 工具链共同承担内核内存安全的全部责任。 /// - Expressiveness. The framework should empower developers to implement a substantial range of OS functionalities in safe Rust using the APIs. It is especially important that the framework enables writing device drivers in safe Rust, considering that device drivers comprise the bulk of the code in a fully-fleged OS kernel (like Linux). // 表现力。 该框架应赋予开发者更多权力。 实现一系列操作系统功能 使用 API 在 Rust 中安全运行。 尤其重要的是…… 该框架支持用安全的 Rust 语言编写设备驱动程序。 考虑到设备驱动程序占据了代码的大部分。 在一个功能齐全的操作系统内核（如 Linux）中。 /// - Minimalism. No functionality should be implemented inside the framework if doing it outside is possible. // 极简主义。 作为内存安全的 TCB， 框架应该尽可能小。 框架内部不应实现任何功能。 如果可以在室外进行的话。 /// - Efficiency. The safe API provided by the framework is only allowed to introduce minimal overheads. Using this framework as a foundation, we have developed the Asterinas Kernel; this framework also enables others to create their own framekernels, with different goals and tradeoffs. // 幸运的是，我们为设计和实现符合这些标准的操作系统框架所做的努力已经取得了成果，即 Asterinas OSTD (. web: asterinas.github.io/book/ostd)。基于此框架，我们开发了 Asterinas 内核；该框架也使其他人能够创建自己的框架内核，以实现不同的目标和权衡。"
